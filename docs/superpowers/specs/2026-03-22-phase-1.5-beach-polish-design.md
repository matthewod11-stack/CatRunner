# Phase 1.5: Beach Level Polish — Design Spec

> **Purpose:** Fix visual quality, gameplay readability, and tuning issues in the Phaser BEACH runner before moving to Level 2.
> **Approach:** Art-First — generate all sprite assets via nanobanana MCP, then wire into Phaser, then tune gameplay against final visuals.
> **Parent:** [ROADMAP_V3.md](../../../ROADMAP_V3.md) (inserted between Phase 1 and Phase 2)

---

## Problem Statement

Playtesting the Phase 1 Phaser port revealed 8 issues:

1. Character and obstacles float mid-air, not aligned with the background ground
2. Background items (plane, boat) are placeholder colored rectangles
3. Boss fight (Sand Monster) — attack mechanic not discoverable, guaranteed loss
4. Level too long and repetitive, too many simultaneous obstacles
5. Sprites too large relative to canvas — cramped, hard to parse
6. TV frame reads as a modern computer monitor, not a 90s VHS/TV combo
7. Sand is a flat tan bar with no texture or variation
8. Sky and ocean are the same blue — no visual distinction

---

## Design Decisions

### 1. Art Pipeline: Sprite-Based Environment via nanobanana MCP

**Decision:** Generate all environment art in the same bold-outline cartoon style as existing sprites (cat, crab, coin, etc.) using the nanobanana MCP (Gemini image generation). Process with the existing `sharp` background-removal pipeline.

**Rationale:** Phaser graphics primitives (gradients, rectangles) clash with the bold-outline cartoon style of the gameplay sprites. Sprite-based art creates visual cohesion. The nanobanana + sharp pipeline is already proven from Phase 1.

**Assets to generate:**

| Asset | Type | Notes |
|-------|------|-------|
| Sand ground tile | Tileable horizontal strip | Warm gradient, grain texture, ~128px tall |
| Ocean water tile | Tileable horizontal strip | Waves, foam detail, darker blue than sky |
| Waterline/foam strip | Narrow tileable | Where ocean meets sand |
| Sky gradient | Static background | Light blue top → warm horizon, visually distinct from ocean |
| Sun | Single sprite | Cartoon sun with rays |
| Cloud (2 variants) | Parallax sprites | Puffy cartoon clouds |
| Boat | Parallax sprite | Bold-outline cartoon style matching crab/cat |
| Boat (sinking) | Parallax sprite | Listing/sinking variant, red-tinted or tilted |
| Airplane | Parallax sprite | Same style |
| Airplane (on fire) | Parallax sprite | Trailing smoke/flames variant |
| Surfer | Parallax sprite | On surfboard, ocean layer |
| Jet ski | Parallax sprite | Small, fast, ocean layer |
| Crab variant 2 | Gameplay sprite | Different pose/color, same hitbox |
| Seagull variant 2 | Gameplay sprite | Slightly different markings |

**Sprite variants:** Multiple versions of the same entity (e.g., 2 crabs) for visual variety. Functionally identical, randomly selected at spawn time.

**Animation approach:** Phaser tweens on single-frame sprites (bobbing boats, drifting clouds, coin rotation, crab walk-cycle via scale flip). No spritesheet animation — keeps the single-frame art pipeline simple.

### 2. Coordinate System Fix + Sprite Scaling

**Ground alignment bug:** `RunnerScene.ts` converts `groundY: 100` to Phaser coords via `groundYScreen = height - themeGroundY`, but player and obstacle Y positioning may not consistently use `groundYScreen` as the reference point. The DOM engine used y=0 at ground with +y up; Phaser uses y=0 at top with +y down.

**Fix scope: render anchoring only — keep world coords.** The scene intentionally uses world-space Y for physics/collisions (`RunnerScene.ts` ~line 862) and converts to screen-space for rendering via `groundYScreen` (~line 1042). Boss projectiles in `bossSystem.ts` also use world-space Y. The fix is **not** to normalize all Y to a single system — it is to ensure every `setY()` / `setPosition()` call in the render path consistently anchors to `groundYScreen`. Physics and collision logic stays in world coords untouched.

**Specific audit targets:**
- Player sprite Y positioning (currently may use raw world Y instead of screen-anchored Y)
- Obstacle/collectible rendering (same issue)
- Boss sprite + projectile rendering
- Ground rectangle anchoring

**Sprite scaling:**
- Current player size: `160x200` px (~33% of canvas height — too large)
- Target player size: ~`96x120` px (~40% reduction, ~20% of canvas height)
- **Approach: scene-wide scale multiplier.** Add `ENTITY_SCALE = 0.6` constant. Config dimensions in `beach.ts` stay as-is (they define proportions). Phaser rendering uses `setDisplaySize(w * ENTITY_SCALE, h * ENTITY_SCALE)`. Collision boxes use the **scaled** dimensions (`w * ENTITY_SCALE`, `h * ENTITY_SCALE` + forgiveness padding).
- Player constants in `RunnerScene.ts` (~line 98: `PLAYER_W`, `PLAYER_H_NORMAL`) become the base values; actual display/collision sizes are `base * ENTITY_SCALE`
- Ground/environment height unchanged

### 3. TV Frame: JVC 4-Head VCR Combo Reference

**Reference:** JVC CRT/VHS combo unit. Critical design values extracted from reference:
- **Body:** Light gray plastic (`#e8e6e2` base, `#d5d2cc` shadow) — NOT silver, NOT beige
- **Proportions:** Screen area ~65% of face height, VCR section ~20%, branding strip ~15%
- **CRT bezel:** ~8px black inner frame with 10px radius corners
- **VCR door:** ~56px tall, inset with label above tape slot
- **Speaker grille:** Right side, ~80px tall, horizontal slats
- **RCA jacks:** Bottom-left, 3 circles (yellow/white/red)

**Changes to `App.tsx` TV frame (find the `{/* Retro TV/VCR Frame */}` comment block):**

| Property | Current | Target |
|----------|---------|--------|
| Body color | Silver metallic gradient | Light gray plastic (`#e8e6e2` → `#d5d2cc`) |
| Corner radius | `rounded-[2.5rem]` (40px) | `rounded-[0.75rem]` (12px) — boxy |
| Screen bezel | 6px dark border | 8px+ black CRT frame |
| Glass effect | Flat + subtle glare | Curved glass (dual radial reflections + barrel shadow inset) |
| Scanlines | 4% opacity | 6-8% opacity |
| VCR section | Minimal slot + tiny buttons | Full treatment (see below) |
| VCR door height | 72px | ~56px (slightly smaller) |
| Speaker | None | Grille on right side of body |
| Branding | "Beach Kitty" small text | Italic weight centered below screen, like "JVC" placement |

**VCR section details:**
- "4 HEAD VCR COMBO / VIDEO CASSETTE RECORDER VHS SQPB" label
- Dark tape slot
- Transport buttons: REC/ITR, REW, PLAY, FF, STOP/EJECT
- Bottom row: RCA jacks (yellow/white/red), CH +/-, VOL +/-, REC indicator LED, POWER button
- Green "CH 03" on-screen display on CRT

**Sizing unchanged:** `85vw / max 1100px / 4:3 aspect ratio`

### 4. Boss Fight Rework

**This is new feature work**, not a bug fix. The current `shootPoop()` mechanic (duck to fire a procedurally drawn projectile) is replaced with a shell-ammo system. This requires new state, new collection logic, and new spawn behavior.

**New state:** Add `shellAmmo: number` field to scene state. Initialized to 0 at run start.

**Shell collection during run:** When player collects a SHELL entity, increment `shellAmmo` in addition to the existing score award (shells = 5 points + 1 ammo). **Shells do NOT advance the coin counter toward boss entry** — only COIN pickups count toward the ~25-30 boss threshold. This keeps boss pacing predictable regardless of shell luck. (Currently `RunnerScene.ts` ~line 897 adds shells to `gameScore.coins`; this must be split so shells only increment a separate `gameScore.shells` or `gameScore.points` value, not the `coins` field that gates boss entry, HUD star counter, and sky progression.)

**Shell collection during boss fight:** Add a boss-phase shell spawn list — periodically spawn SHELL pickups on the ground (every ~3-4 seconds) so the player is never stuck with zero ammo.

**Boss entry ammo guarantee:** Shells collected during the run carry over as starting boss ammo. If `shellAmmo === 0` when boss triggers, immediately spawn 3 shells on the ground **and** the boss delays its first attack by ~2 seconds (intro window with hint text). This prevents the "guaranteed loss" problem from surviving the redesign.

**Shooting:** Rename/rework `shootPoop()` → `shootShell()`. Guard with `if (shellAmmo <= 0) return`. Decrement `shellAmmo` on fire. Visual projectile changes from procedural graphic to shell sprite.

**Boss HP:** Set `health: 20`, keep `damagePerHit: 4`. This gives a 5-hit fight. (~20-30 seconds total.)

**Bug fixes (coordinate system):**
- Fix projectile spawn Y to use `groundYScreen` (same coordinate fix as Section 2)
- Verify boss hitbox aligns with sand-monster sprite at new scaled size

**Discoverability:**
- On boss entry, flash text hint: "Press DOWN to throw shells!" (fades after 2-3 seconds)
- Visual ammo counter in HUD during boss fight (e.g., "Shells: 7") — also serves as a cue
- If ammo is 0, show pulsing "Grab shells!" prompt

**HUD bridge for shell ammo:** The current HUD bridge (`onHudUpdate` in `PhaserGame.tsx` → `App.tsx`) only handles pause state. Extend `HudUpdatePayload` (in `scenes/shared/bridgeProtocol.ts`) to include `shellAmmo?: number`. The in-screen HUD in `App.tsx` (~line 781) conditionally renders a shell counter when `status === BOSS_FIGHT && shellAmmo !== undefined`.

### 5. Pacing & Difficulty Tuning

**Speed:** Remove aggressive speed scaling. The current `speedIncrement: 0.002` (in `systems/tuning/defaultTuning.ts`) ramps speed continuously, turning late-run into a reaction-speed test. Change to `speedIncrement: 0.0003` and add `maxSpeed: 8.5` cap (base `initialSpeed` is `7.5`, giving a ~13% max ramp). This replaces the speed-based difficulty curve with a composition-based one.

**`maxSpeed` is a tuning-contract change** affecting multiple files:
- `TuningProfile` interface in `systems/tuning/defaultTuning.ts` — add `maxSpeed: number` field
- `DEFAULT_TUNING` object — add `maxSpeed: 8.5`
- `TUNING_RANGES` metadata — add range entry for `maxSpeed` (e.g., `{ min: 6, max: 15, step: 0.5 }`)
- `BalancePanel.tsx` (~line 10) — automatically picks up new field since it enumerates `keyof TuningProfile`
- `RunnerScene.ts` (~line 432) — add speed clamp: `this.speed = Math.min(this.speed, this.tuning.maxSpeed)`

**Difficulty = obstacle composition (3 phases):**

| Phase | Time | What Spawns | Feel |
|-------|------|-------------|------|
| Early | 0-20s | Single obstacles (lone crab, single coin arc, beachball) with generous gaps | Warmup, learn the controls |
| Mid | 20-40s | Combos (crab + low seagull, sandcastle + coin trail, paired obstacles) | Engaging, readable patterns |
| Late | 40-60s | Dense patterns (seagull swoop → poop → crab, multi-obstacle gauntlets) + power-up spawns | Intense but still parseable |

**Boss entry:** ~25-30 coins (tuned so it hits around 60 seconds at near-constant speed).

**Spawn margin:** Change obstacle spawn X from `canvasWidth + 200` (current, in `RunnerScene.ts` lines ~678, ~705) to `canvasWidth + 300`, giving ~100px more visual warning / reaction time. Background entity spawn offset (`backgroundSpawn.ts`) stays unchanged.

**Pattern weighting:** Existing 8 patterns weighted by phase — simple patterns dominate early, complex patterns only appear in late phase. Currently all equally likely from the start (uniform random selection at `RunnerScene.ts` ~line 551).

**Schema change required:** The current pattern type is `PatternStep[][]` (in `types.ts` ~line 373) with no phase metadata. Add a wrapper type:
```typescript
interface PhasedPattern {
  phase: 'early' | 'mid' | 'late' | 'any';  // 'any' = all phases
  steps: PatternStep[];
}
```
Update `LevelConfig.patterns` type from `PatternStep[][]` to `PhasedPattern[]`. Selection logic in `RunnerScene.ts` filters available patterns by current phase (determined by elapsed time: 0-20s = early, 20-40s = mid, 40s+ = late). `types.ts` is an affected file.

### 6. Environment Rendering in Phaser

**Replace flat primitives with layered sprite composition:**

| Layer | Depth | Content | Motion |
|-------|-------|---------|--------|
| Sky | 0 | Static gradient (generated sprite or Phaser gradient fill) | None |
| Sun | 1 | Sun sprite, top area | Gentle pulse tween (scale 1.0 → 1.05) |
| Clouds | 2 | 2 cloud variants; update `beach.ts` cloud `spawnYRange` from `{ min: 0.55, max: 0.7 }` to `{ min: 0.05, max: 0.25 }` so clouds appear in the sky, not the ocean | Slow parallax drift (0.2x game speed) |
| Airplane/Boat | 3 | Background objects (generated sprites) | Medium parallax (0.4x), boat bobs gently |
| Ocean | 4 | Water tile spanning mid-screen | Subtle horizontal oscillation tween |
| Waterline foam | 5 | Narrow strip where ocean meets sand | Shimmer / opacity pulse |
| Sand | 6 | Sand tile at bottom | Static (anchored to ground) |
| Gameplay entities | 10+ | Cat, obstacles, coins, shells, boss | Full speed, grounded on sand surface |

**Readability improvements:**
- Obstacle spawn X increased from `canvasWidth + 200` to `canvasWidth + 300`
- Bold black outlines on all sprites naturally create contrast against background
- Distinct sky/ocean/sand layers prevent visual confusion

## Implementation Sequence (Art-First)

1. **Generate environment sprites** via nanobanana MCP + sharp background removal
2. **Generate sprite variants** (crab v2, seagull v2)
3. **Fix coordinate system** — audit all Y positioning in `RunnerScene.ts` to use `groundYScreen`
4. **Scale down sprites** — player to ~96x120, proportional scaling for all entities
5. **Replace Phaser primitives** with sprite assets + layer composition + parallax + tweens
6. **Restyle TV frame** — JVC reference CSS in `App.tsx`
7. **Rework boss fight** — shell ammo system, `health: 20` (5-hit fight), HUD bridge for ammo, visual hint, fix projectile Y
8. **Tune pacing** — constant speed, composition-based difficulty ramp, wider spawn margin, ~60s to boss, phase-weighted patterns
